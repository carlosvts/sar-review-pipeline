# Decisões de projeto

## Snowballing no método do Wohlin (19/11/2026)

- **Uma rodada = backward e forward juntos, com a triagem completa antes da rodada seguinte.** Decidido com o orientador para seguir a metodologia original do Wohlin. Em cada rodada, os selecionados da rodada anterior (na rodada 1, o start set) passam por backward e forward ao mesmo tempo. Os works novos passam pela triagem por título, pelos abstracts e clusters e pela leitura do texto completo, e só os incluídos no texto completo (`r<N>/selected.jsonl`) viram os seeds da rodada seguinte. Substitui as duas cadeias independentes de 15/11/2026, cuja fronteira era só o corte por título e que inchavam o conjunto (o forward chegou a 11.593 works em 7 rodadas).
- **A triagem de cada rodada vai até o texto completo.** A decisão do texto completo é humana e fica em `r<N>/fulltext/decisions.csv` (`include`/`exclude` e motivo). O `select` não roda com linha pendente.
- **Todo selecionado é seed**, inclusive um `needs_context` que passou no abstract e no texto completo. A regra antiga, de que só `passed_title` alimentava a fronteira, caiu.
- **O clustering é refeito em toda rodada.** Sweep, fit e a decisão do K e dos clusters excluídos são tomados por rodada (`DECISIONS[N]` em `abstracts/include.py`), cada um citando o tema e o `assignments` de onde vem o número.
- **Work já visto é ignorado.** Um work que apareceu em qualquer rodada anterior, por qualquer direção, não volta (comparação por ID do OpenAlex e por DOI). Achado pelas duas direções na mesma rodada, entra uma vez com `direction = "both"`; `hits.jsonl` guarda cada aresta seed → work.
- **Tudo rebuscado do zero.** A coleta nova não reaproveita as respostas antigas do OpenAlex e do Semantic Scholar, nem o cache de abstracts e os PDFs: grava tudo em `data/rounds/`. Os dados da pipeline anterior (`data/jsonl`, `data/raw`, `data/cluster`, `data/fulltext`, `data/abstracts`) ficam como estão, só como histórico.
- **O start set é a rodada 0.** Entra como selecionado, sem triagem, e tem o texto completo baixado como qualquer selecionado.

## Pipeline anterior (até 15/11/2026, histórico)


- **JSON bruto e JSONL têm papéis diferentes.** O JSON bruto é cache e prova do que a API devolveu. O JSONL traz só os campos úteis ao filtro da etapa 02 e é o formato de trabalho das etapas seguintes.
- **Abstract ausente só exclui quem o título não aprovou.** Um `passed_title` sem abstract segue pelo título e terá o texto completo buscado depois. Um `needs_context` sem abstract em nenhuma fonte sai com `exclusion_reason = "sem_abstract"`, registrado para o PRISMA, porque não há como decidir o contexto dele.
- **A etapa 03 não usa LLM.** A recuperação, a validação e o agrupamento são determinísticos; a decisão de exclusão é humana, por cluster, conferindo os artigos de borda.
- **O ajuste do KMeans usa só quem tem abstract.** Vetores feitos só de título não puxam os centroides; os `title_only` são atribuídos depois, ao centroide mais próximo.
- **Exclusão por cluster (14/11/2026): mpnet, cosseno, K=10.** Saem quatro temas: robôs humanoides (NAO) em terapia de crianças com TEA, SAR para idosos em casa e em lares, robótica social geral sem tema específico e robôs sociais na educação de crianças. Na análise original (`results/clustering/mpnet_cosine_k10/`, 1.360 artigos) eles eram os clusters 0, 1, 3 e 9; na execução de 14/11/2026 (`data/cluster/mpnet/cosine/assignments_k10.csv`, 1.357 artigos), que é a usada na seleção, são os clusters 2, 6, 3 e 4. Ficam 749 artigos, que vão para `included.jsonl`, mais os 16 do start set na etapa 04.
- **Cluster se identifica pelo tema, não pelo número.** O fit é determinístico para a mesma entrada, mas a entrada muda entre execuções (as APIs da etapa 03 devolvem abstracts um pouco diferentes: 1.201 válidos na análise original, 1.197 em 14/11/2026). Com outra matriz, o `kmeans_plusplus` parte de outros centros, as fronteiras se deslocam e os rótulos 0 a K-1 são renumerados. Toda decisão por cluster cita o tema e o `assignments_k{K}.csv` de onde vem o número.
- **`abstract_source` registra a origem de cada abstract**, para que as fontes adicionadas na etapa 03 fiquem rastreáveis.
- **O start set é rebuscado a cada execução; o backward é acumulado.** `load_backward()` carrega do disco as rodadas anteriores, e só os IDs ainda não vistos são buscados.
- **Backward e forward são duas buscas independentes a partir do start set, não um loop único (15/11/2026).** O protocolo (4.3) descreve backward e forward a cada iteração, com a fronteira vindo das duas direções. Aqui são duas cadeias separadas: start set → backward recursivo até convergir, e start set → forward recursivo até convergir. Cada direção só expande o que ela mesma achou: os elegíveis do forward não têm as referências buscadas, e os do backward não têm as citações buscadas. Os `needs_context` também não alimentam a fronteira, porque só `passed_title` vira seed.
- **Primeira tentativa de forward descartada (15/11/2026).** Uma rodada de forward usando como seeds o start set e os 749 incluídos do backward (765 seeds) trouxe 28.898 works novos e 1.524 `passed_title` numa única rodada. Isso misturava as rodadas do backward com o forward e expandia a partir de artigos ainda não confirmados no texto completo. Os arquivos foram apagados e o forward foi refeito só a partir do start set.
- **Só o código da coleta depende da direção.** Triagem por título, abstracts, clustering e inclusão são o mesmo código para as duas direções, trocando só os arquivos (`direction.py`); o backward manteve os caminhos de antes do forward. A etapa 04 baixa a união: start set, `included.jsonl` e, quando existir, `forward_included.jsonl`.
- **O forward usa o OpenAlex como formato comum.** As citações vêm do OpenAlex (`cites:`) e do Semantic Scholar; o que só o Semantic Scholar conhece é buscado no OpenAlex pelo DOI, para todo work ter o mesmo `Work` e o mesmo ID. O forward não descarta o que o backward já viu: a sobreposição entre as direções é resolvida na etapa 04, que baixa a união sem repetir works. Citações sem DOI no Semantic Scholar não têm como ser cruzadas e só são contadas.
- **A fronteira do forward segue a regra do backward:** só `passed_title` vira seed da rodada seguinte. Se o volume crescer demais, `--max-rounds N` aplica o limite de iterações previsto no protocolo (4.4), que precisa ser registrado aqui com a justificativa.
- **`save()` reescreve os arquivos inteiros.** Por isso, `load_backward()` precisa ser chamado antes de `fetch_backward()` e `save()`: sem ele, o que foi acumulado nas rodadas anteriores é sobrescrito.
- **A etapa 04 pode ser rodada de novo sem refazer trabalho.** Um arquivo válido já baixado não é baixado de novo, o manifesto não toca nas linhas que já existem ao ser gerado, e a extração pula o JSONL que é mais novo que o documento de origem.
- **`status = manual` nunca é sobrescrito.** É o valor para marcar no manifesto um texto recuperado à mão; o download seguinte não altera essa linha.
- **Arquivos são gravados em `.part` e renomeados no final.** Uma queda no meio do download, da extração ou da escrita do manifesto não deixa arquivo corrompido.
- **Texto completo não encontrado nunca significa exclusão.** O work vai para a fila manual, com os links e o motivo da falha de cada candidata.
- **Dentro da fonte `pmc`, o XML é tentado antes do PDF renderizado.** O JATS já traz seções e parágrafos marcados, o que dispensa as heurísticas de layout do PDF.
